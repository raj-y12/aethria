# Deployment Notes

This cleanup intentionally preserves the current deploy roots:

- `app-front-end`
- `web-front-end`
- `backend`

Do not move these folders into `apps/`, `services/`, or another workspace layout until Vercel and Render settings are changed together.

## App Frontend

Deploy root: `app-front-end`

Build assumptions:

- Package manager: npm, using `app-front-end/package-lock.json`
- Build command: `npm run build`
- Build script: `tsc && vite build`
- Output directory: `dist`
- SPA routing: `app-front-end/vercel.json` rewrites non-asset routes to `/index.html`

Local commands:

```bash
cd app-front-end
npm install
npm run dev
npm run build
```

## Web Frontend

Deploy root: `web-front-end`

Build assumptions:

- Package manager: npm, using `web-front-end/package-lock.json`
- Build command: `npm run build`
- Build script: `tsc && vite build`
- Output directory: `dist`
- SPA routing: `web-front-end/vercel.json` rewrites non-API routes to `/index.html`
- Serverless waitlist endpoint: `web-front-end/api/waitlist.ts`

Local commands:

```bash
cd web-front-end
npm install
npm run dev
npm run build
```

## Backend

Deploy root: `backend`

Start command assumption:

```bash
uvicorn api:app --host 0.0.0.0 --port $PORT --workers 1
```

Local command:

```bash
cd backend
python3 -m uvicorn api:app --reload --host 0.0.0.0 --port 8000
```

The root `run.py` also assumes `backend`, `app-front-end`, and `web-front-end` exist at the repository root. It starts the backend with `python -m uvicorn api:app` from `backend/`, then starts both Vite dev servers from their current deploy roots.

### Docker (local backend)

For containerized local backend runs, see [docker.md](docker.md). Build context is the repo root; Render deployment is unchanged.

## Generated Files

Frontend `dist/` folders are generated by Vite and should not be committed. Vercel rebuilds them from each frontend deploy root.
